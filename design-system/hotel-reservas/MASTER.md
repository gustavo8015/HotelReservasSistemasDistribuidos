## Style Guidelines

**Style:** Liquid Glass

**Keywords:** dynamic material, optical glass, translucency, lensing, refraction, fluid morphing, system navigation

**Best For:** Apple-platform navigation, controls, and system-aligned app chrome

**Key Effects:** Lensing and refraction, adaptive translucency, and fluid morph transitions aligned to Apple platform behavior

### Page Pattern

**Pattern Name:** Hero + Testimonials + CTA

- **Conversion Strategy:** Social proof before CTA. Use a concise set of verified testimonials with photo, name, and role. CTA after social proof. Provide previous/next and pause controls; stop rotation on focus, hover, and reduced motion; announce slide position. Previous/next buttons and keyboard controls must expose every slide without dragging.
- **CTA Placement:** Hero (sticky) + Post-testimonials
- **Section Order:** Hero > Problem statement > Solution overview > Testimonials carousel > CTA

## Motion

**Scroll Reveal** (Subtle) — Trigger: scroll (viewport enter) | Duration: 300-400ms | Easing: `power1.out`

```js
gsap.from(el, { opacity: 0, y: 12, duration: 0.35, ease: 'power1.out', scrollTrigger: { trigger: el, start: 'top 90%', toggleActions: 'play none none reverse' } });
```

**Framework notes:** Requires the ScrollTrigger plugin registered once via gsap.registerPlugin(ScrollTrigger); Use matchMedia('(prefers-reduced-motion: reduce)') to skip non-essential motion and render the final state immediately

- ✅ Keep the y offset small (8-16px) so it reads as a fade, not a slide
- ❌ Don't reveal below-the-fold content needed for SEO/crawlers as invisible-by-default without a no-JS fallback
- ⚡ toggleActions 'play none none reverse' avoids re-triggering on every scroll direction change

## Anti-Patterns (Do NOT Use)

- ❌ Poor photos
- ❌ Complex booking

### Additional Forbidden Patterns

- ❌ **Emojis as icons** — Use SVG icons (Heroicons, Lucide, Simple Icons)
- ❌ **Missing cursor:pointer** — All clickable elements must have cursor:pointer
- ❌ **Layout-shifting hovers** — Avoid scale transforms that shift layout
- ❌ **Low contrast text** — Maintain 4.5:1 minimum contrast ratio
- ❌ **Instant state changes** — Always use transitions (150-300ms)
- ❌ **Invisible focus states** — Focus states must be visible for a11y

## Pre-Delivery Checklist

Before delivering any UI code, verify:

- [ ] No emojis used as icons (use SVG instead)
- [ ] All icons from consistent icon set (Heroicons/Lucide)
- [ ] `cursor-pointer` on all clickable elements
- [ ] Hover states with smooth transitions (150-300ms)
- [ ] Light mode: text contrast 4.5:1 minimum
- [ ] Focus states visible for keyboard navigation
- [ ] `prefers-reduced-motion` respected
- [ ] Responsive: 375px, 768px, 1024px, 1440px
- [ ] No content hidden behind fixed navbars
- [ ] No horizontal scroll on mobile

## Decisiones aplicadas en Hotel Reservas (31 de octubre de 2026)

Esta sección registra cómo se llevó la recomendación anterior al código real de la aplicación web, y
dónde se decidió apartarse de ella. Las variables vivas están en `HotelReservas.Web/wwwroot/css/app.css`,
en el bloque `:root` del comienzo del archivo; cambiar un valor allí lo cambia en toda la aplicación.

**Color.** Se conservó el azul institucional del proyecto, `#0B2A5B`, en lugar del `#1E3A8A` sugerido:
es el color con el que ya está escrita la documentación de las fases I a III y tiene mejor contraste
(14,0:1 con texto blanco). Sí se adoptó el dorado de hostelería `#A16207` como color de la llamada a la
acción, que antes era verde. El verde `#1F6B3D` quedó reservado para los estados correctos, es decir
disponible, confirmado y los totales, de modo que cada color significa una sola cosa. Las diecinueve
combinaciones de texto y fondo del sistema se verificaron y todas superan la relación 4,5:1 que exige
el criterio 1.4.3 de las WCAG 2.2.

**Tipografía.** Playfair Display SC para los títulos y Karla para el texto, que es el emparejamiento que
el sistema propone para hostelería, con Georgia y Segoe UI declaradas como alternativa: si el equipo está
sin internet, las fuentes del sistema mantienen el mismo aire editorial. El cuerpo subió de 14 a 16 px
con interlineado 1,55 y ningún texto quedó por debajo de 12 px.

**Accesibilidad.** Anillo de foco visible en todo control, salto al contenido como primer tabulador,
botones y campos de 44 px de alto, avisos con `role="alert"` o `role="status"` para que el lector de
pantalla los anuncie, y la tarjeta de habitación convertida en botón real para poder reservar sin ratón.
Se respeta `prefers-reduced-motion`.

**Movimiento.** Nivel 3 de 10, es decir micro interacciones: transiciones de 140 a 220 ms en botones,
campos y tarjetas. No se usa GSAP ni animación de entrada en el desplazamiento, porque la aplicación es
de gestión y la animación larga estorba al operador.

**Lo que no se adoptó.** El estilo Liquid Glass y el patrón de página de aterrizaje con carrusel de
testimonios: el primero depende de desenfoques costosos y de la estética de las plataformas de Apple, y
el segundo corresponde a una página comercial, no a un sistema transaccional con sustentación académica.
